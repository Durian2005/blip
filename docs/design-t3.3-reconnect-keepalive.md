# T3.3 断线重连与保活 编码前设计

> 定位：WBS T3.3——「断线重连（指数退避 1/2/4/8/15s）+ 应用层 PING 保活」，
> 验收判据「走出范围再走回，≤15 s 自动恢复」。
> PRD v1.4 §7.4.1 留白的「拓扑不符换边重连」的连接层细节也在本文落定。

## 0. 一句话结论

**重连器与保活都只做决策，不做数据**。`IByteChannel` 是单读者契约（P2 固化），
读字节的永远是会话泵（将来的消息循环）；重连器只监听**链路生命周期**，
保活只回答「现在该不该发 PING / 该不该判死」。两者全部做成纯逻辑 +
可注入时钟/延迟，真机验收只是把它们接上电。

## 1. 职责分层（谁碰什么）

| 层 | 组件 | 碰数据吗 | 职责 |
|---|---|---|---|
| 通道层（T3.1 ✅） | Ble 两侧通道 | 只搬运字节 | 断链时 `ReceiveAsync` 返回 0 + 事件 |
| **重连器**（本文） | `ConnectionSupervisor` | **否** | 失链 → 退避 → 重建通道；成功/断开事件 |
| **保活**（本文） | `KeepalivePolicy` | **否**（决策） | 该发 PING？等 PONG 超时？ |
| 会话泵（后续） | 消息循环 | 是 | 读字节 → 帧层 → 消息；执行保活决策 |

关键推论：**重连器不知道 PING/PONG**，保活不知道通道重连。会话泵发现链路死
（保活判死 / `ReceiveAsync` 读到 0 / Ble 事件 / SendAsync 抛 IOException）→ 调
`supervisor.ReportLinkLost()` → 重连器接管。职责单一，测试各自独立。

## 2. 决策 A：退避序列 1/2/4/8/15s，封顶后恒 15s

- WBS 与验收口径（≤15 s 恢复）直接给出序列：**1 → 2 → 4 → 8 → 15 → 15 → …**
- **不加随机抖动**：这是 1:1 链路，不存在"多客户端同步重试打爆对端"的场景；
  抖动只会让重连时间不可预测、测试变难。确定性优先（与竞选键哲学一致）。
- **连接成功即归零**（`Reset()`）：半开链路上的一次成功必须把计数清掉，
  否则一次蓝牙范围外的 10 分钟会导致之后永远 15 s 才重连。
- 首次连接**不走退避**（第 0 次尝试立即执行）。

## 3. 决策 B：重连器如何区分两侧角色 —— 它不区分

`ConnectionSupervisor` 对角色**一无所知**：它只拿一个
`Func<CancellationToken, Task<IByteChannel>> connect` 工厂委托。
角色语义全在工厂里：

| 角色 | 工厂内容 | 失败语义 |
|---|---|---|
| 中心 | `BleGattCentralChannel.StartAsync(TargetAddress: 已知地址)` | 抛异常 = 本次尝试失败 |
| 外设 | `BleGattPeripheralChannel.StartAsync()` → 等首个订阅者（`ClientConnected`） | 抛异常 / 等待被取消 = 失败 |

这把「中心直连重试」与「外设重启广播等回来」统一成同一套退避循环，
新增通道类型（RFCOMM 降级方案，R1 备胎）时重连器零改动。

配套改动：`BleGattPeripheralChannel` 补 `ClientConnected` 事件
（订阅者 0 → >0 时触发，与 `ClientDisconnected` 的 >0 → 0 对称）——
外设侧没有它，工厂就表达不出「链路已建立」。

## 4. 决策 C：保活对称化（PRD §7.5 修订 v1.4 → v1.5）

PRD 原文「外设侧 20 s 无流量则发」改为**两侧对称**：

- Windows 栈的静默断链**不分角色**——中心同样会遇到"链路还在但对方早已消失"；
- 外设单侧发 PING 探不出「中心死了但订阅者还没掉」的窗口（实测 P1 里订阅事件有延迟）；
- 对称实现让会话泵只有一套逻辑。

规则（`KeepalivePolicy`，全部由时间戳驱动，不持有定时器）：

| 状态 | 条件 | 动作 |
|---|---|---|
| 空闲 | 距上次任何流量 ≥ **20 s** 且无未决 PING | `SendPing` |
| 等待 | 已发 PING 且 < **10 s** | `None`（PONG 未到再等） |
| 判死 | 已发 PING 且 ≥ **10 s** 无任何流量 | `DeclareDead` → 泵调 `ReportLinkLost()` |
| 任何收发（含 PONG） | — | 计时归零 |

- 参数：`IdlePingMs = 20000`（PRD 原值）、`PongTimeoutMs = 10000`。
  判死最坏延迟 ≈ 30 s，远大于 15 s 重连预算，但 WBS 的 ≤15 s 指**断链感知后**
  的重建时间（范围走回本身 BLE 就有链路层断开事件，多数场景走不到 PING 判死）。
- PING/PONG 是单帧控制帧，旁路重组器——`FrameTypes.IsFragmented` 已登记（P2 修 2），
  无需改动。

## 5. 决策 D：拓扑不符换边（PRD v1.4 §7.4.1 第 2 条的落地）

PRD v1.4 把选举挪到连接后：读对端 META → `RoleElection`（T3.2 纯逻辑）出结果 →
若结果与当前拓扑不符则换边。流程：

```
连接建立（任一方为临时中心）
  → 双方各读对端 META（通道已暴露 MetaPayload）
  → 各自跑 RoleElection（输入：己方能力档案 + 对端能力位 + 两个竞选键）
  → 两端结果必然一致（纯逻辑，200 组性质测试保证）
  ├─ 一致且拓扑匹配 → 进入会话
  └─ 不匹配 → 该当外设的一方：发 BYE → 断开 → 重启广播等待
              该当中心的一方：收到 BYE/读 0 → 退避 → TargetAddress 直连重连
```

**为何换边不会被同时触发**：选举是确定性纯函数，两端输入一致则输出一致；
「谁主动断开」由选举结果唯一决定（该当外设者断），不存在双断或双等的死锁。

**本阶段实现边界**：`RoleElection` 与 `MetaPayload`（T3.1 已暴露）都已就绪，
但 HELLO/HANDSHAKE 的会话握手（P4）还不存在，META 的能力位语义也未接进会话。
换边的**编排**属于会话层，本批只交付它依赖的底座（重连器 + 退避 + 直连参数）。
换边编排标记为**留白**，随会话泵一起落地。

## 6. 状态机

```
Idle ──Start()──▶ Connecting(0) ──成功──▶ Connected ──ReportLinkLost()──┐
   ▲                    │失败                                            │
   │                    ▼                                                │
   └──Stop()── Backoff(n) ◀────────────────────────────────────────────────┘
                  │  等待 min(2^(n-1), 15)s 后重试
                  ▼
              Connecting(n) ──成功──▶ Connected（退避归零）
                  │失败
                  ▼
              Backoff(n+1)（封顶 15 s）
```

- `Connected` / `Disconnected` 事件给上层（UI 状态栏"重连中"）。
- `StopAsync` 取消一切等待并关闭当前通道；幂等。
- `ReportLinkLost` 幂等：非当前通道的失联报告直接忽略（旧通道的迟到事件）。

| # | 验证项 | 判据 | 怎么验 |
|---|---|---|---|
| 1 | 退避序列 | 1/2/4/8/15/15…，成功归零 | 单测 ✅ |
| 2 | 重连循环 | 连续失败 N 次后成功，事件序列正确 | 单测（假工厂）✅ |
| 3 | 幂等 | Stop/ReportLinkLost 重复调用无副作用 | 单测 ✅ |
